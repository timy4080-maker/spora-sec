## N1. Изоляция карантина

TX1 резервирует место для всей страницы перед фиксацией cursor и созданием заданий consume. И pending, и quarantined занимают резерв до разрешения записи. При заполнении бюджета клиент оставляет всю новую страницу на Relay, продолжает опрос других источников и через секунду пробует получить одну запись. Перезапуск сохраняет состояние очереди. Уменьшение страницы помогает использовать оставшееся место. Полностью занятый бюджет требует обработки ранее принятых данных.

| Область учёта | Число записей | Объём |
|---|---:|---:|
| Все незавершённые входящие | 1024 | 4 MiB |
| Все выделенные очереди одного отпечатка | 128 | 1 MiB |
| Очереди с общей или неизвестной историей выдачи, вместе | 256 | 2 MiB |
| Каждая очередь в этой общей группе | 64 | 512 KiB |

Для каждой записи учитывается длина base64url-конверта плюс 1024 байта резерва на метаданные. Владелец квоты определяется локальной историей выдачи write capability. Это атрибуция очереди для допуска. Подлинность отправителя устанавливает libsignal в TX2. При выдаче второму отпечатку очередь постоянно переходит в общую группу. Уже принятые записи сохраняют своё отнесение к квоте. Для старых профилей отсутствующая история выдачи означает общую группу. Прежние сообщения и сессии остаются доступны. Другие отправители в одной общей очереди зависят от её cursor, а для всего профиля по-прежнему действуют общие пределы и объём свободного диска.

После срока хранения приглашения GC проверяет, ссылается ли сохранённый pending или quarantined конверт на конкретный комплект prekeys. Для этого открывается обёртка исходного маршрута, проверяются устройство назначения, тип prekey-сообщения и согласованность EC, signed и KEM ID. Для известного собеседника дополнительно проверяются registration и владелец комплекта. Для ещё не сопряжённого собеседника сохраняется названный комплект. GC сохраняет исходный конверт. Поздний повтор после очистки digest-кэша всё ещё может занять место в карантине и удержать один относящийся к нему комплект.

Проверки охватывают заполнение квоты одной очереди, обработку текста другого устройства, сохранение обеих отложенных копий на Relay, повторный fetch после перезапуска и удержание нужного комплекта при очистке постороннего. [Тест с Relay](../tests/integration.rs) · [тесты хранения и границ](../src/review_tests.rs).

## N2. Версия подписываемого приглашения

Кодировщик проверяет `version == 2` при каждом вызове и записывает в CBOR значение поля. Прежний эталонный вектор совпадает побайтно. Версии 0, 1, 3, 255 и отсутствующее поле отвергаются при запросе подписываемых байтов. Значение по умолчанию сохранено для чтения старых локальных записей. [Кодировщик](../src/model.rs) · [эталонный вектор](../tests/fixtures/bootstrap-v2.json).
